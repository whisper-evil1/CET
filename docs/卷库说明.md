# 卷库说明（2021.06 – 2026.06，四级 33 套 / 六级 33 套）

这份文档说明卷库里每一套卷子从哪来、怎么进库、哪些地方是按官方题型做的、哪些地方是
有意做的简化。**先看「内容来源」这一节再看别的**——它决定了这套卷子能不能被称作真题。

当前状态：66 套全部 `status=ready`，共 2112 道题（每套 32 题：写作 1 + 阅读 30 + 翻译 1），
另有两套早期示例卷置 `hidden`（数据保留、不进列表）。

## 一、内容来源（必须知道的一条）

`Paper.origin` 有两个值：

| 值 | 含义 | 界面标注 |
| --- | --- | --- |
| `official` | 可核实的官方原题 | 官方原题 |
| `simulated` | 按官方题型结构与难度编写的仿真材料 | 仿真材料 |

当前 66 套全部是 `simulated`。原因很直接：官方真题的听力音频、阅读原文属于版权内容，
本项目拿不到授权，也不会把自写文章冒充成官方原题。仿真材料做到的是：

- 卷面结构、题号、分值分布、时间与官方一致；
- 文章题材、长度、难度按级别控制（四级 4,500 词以内词汇、六级 5,500 词）；
- 题目是原创的，解析是中文写的，能讲清"为什么对、为什么错"。

考试大纲的结构对照：

| 部分 | 四级 | 六级 | 本卷库 |
| --- | --- | --- | --- |
| Section I Writing | 30 分钟，120–180 词 | 30 分钟，150–200 词 | ✅ 题干 + 参考范文 |
| Section II Listening | 25 分钟，25 题 | 30 分钟，25 题 | ⚠️ 只建结构，无音频（见下） |
| Section III Reading | 40 分钟，30 题（26–55） | 40 分钟，30 题（26–55） | ✅ 四篇齐全 |
| Section IV Translation | 30 分钟，1 题（56） | 30 分钟，1 题（56） | ✅ 题干 + 参考译文 |

## 二、听力为什么是空的

听力要音频才成立，没有音频的听力题就是"看不到材料却要选答案"的死题。所以：

- 卷子里保留 `Section II` 的位置与时长（结构完整），但标题标注「音频暂缺」；
- **不入听力题**：闯关与刷题都不会抽到听力，避免出现无材料的题面；
- 未来接入音频后，按 `data/papers/<id>.json` 里的 listening 段补题即可，导入器已经支持
  `passage.audioUrl` / `transcript`，题数校验是 25 题。

## 三、题型细节与取舍

### Section A 选词填空（26–35）

官方形态是「一篇短文挖 10 个空 + 一个 A–O 十五词词库」。正文 JSON 允许按「每空四选一」
写（更好写、也不容易把词性写错），导入时由 `scripts/lib/wordbank.mjs` 统一升级：

1. 10 个空的正确词 = 词库里的 10 个必用词；
2. 从各空原有干扰项里取 5 个最常出现的词补足 15 词；
3. 15 个词按字母序编号 A–O（字母序可以避免"答案顺序即题号顺序"这种泄题规律）；
4. 每道题的选项换成同一个词库，`answer` 按词重映射成新字母；
5. 正文末尾补一段 `label=词库` 的段落，读原文时就能看到词库。

这个升级是幂等的：已经是十五词词库的卷子原样通过，不会二次改造。

### Section B 长篇阅读匹配（36–45）

官方是 15 段（A–O）配 10 道陈述。本卷库按 **6–8 段**编排，题量仍是 10 题、选项是段落
字母。这是有意做的简化：把 15 段、约 1,000 词的长文压到 6–8 段 350 词，才能在同样时间
里把 66 套都写扎实。**这一点会影响"段落多、干扰强"的原始难度**，选择练习时要留意。

### Section C 仔细阅读（46–55）

两篇各 5 题，四选一，与官方一致。每道题都带 `analysis`（中文解析）与
`evidencePara` / `evidenceText`（原文依据），刷题页可以在解析里定位到那句话。

### 写作与翻译（第 0 题 / 第 56 题）

- 写作：`stem` 是题目要求，`analysis` 是完整参考范文（四级 ≥140 词、六级 ≥170 词）；
- 翻译：`stem` 是中文段落，`analysis` 是英文参考译文 + 3–5 条要点。

写作/翻译面板读的就是 `question.analysis`（见 `writing-translation-pane.tsx`），
所以这两段内容不是装饰，是功能的一部分。

## 四、入库流程

```
data/papers/<paperId>.json      # 正文，文件名必须等于卷 id
scripts/papers-catalog.mjs      # 66 套目录（唯一事实来源：年月、套号、时长、排序）
scripts/lib/wordbank.mjs        # 选词填空词库化（纯函数）
scripts/normalize-wordbank.mjs  # 把词库化结果写回 JSON（可选，导入器也会在内存里做）
scripts/import-papers.mjs       # 校验 + 入库
```

常用命令：

```bash
node scripts/papers-catalog.mjs                    # 打印 66 套目录
node scripts/import-papers.mjs                     # 全量校验并入库
node scripts/import-papers.mjs --only cet4-2025-06-s1   # 只处理一套
node scripts/import-papers.mjs --check             # 只校验，不写库
node scripts/normalize-wordbank.mjs                # 把词库写回 JSON
node scripts/e2e-papers.mjs                        # 卷库验收（结构 + 接口）
```

三条不可破坏的规则：

1. **幂等**：所有 id 都是确定的（`<paperId>-sec-<order>` / `-p-<secOrder>-<i>` /
   `-q-<number>-<passageIndex>`），重复导入只更新不新增；
2. **不碰用户数据**：只重建本卷的 section/passage/question，题目 id 稳定，`Answer` 挂在
   `questionId` 上，改题不会连带清掉别人的作答；
3. **没正文就是 draft**：结构照建、`status=draft`，列表可见但不可练，闯关只抽
   `status=ready` 的卷。

## 五、draft 卷的处理

- 首页列表里 draft 卷正常显示，但标「待补」且不给入口（点进去是空卷，比不给入口更糟）；
- `/api/papers/[id]` 对 draft 卷返回 404，闯关拿不到它；
- 刷题页 `practice/[paperId]` 遇到 draft 直接跳回首页试卷区。

也就是说，卷库可以「先有目录、后补正文」，中间态不会漏出半个空卷给用户。

## 六、两张早期示例卷去哪了

`paper-cet4-2024-12` / `paper-cet6-2024-06` 是 v2.x 时 seed 进去的示例卷（各 5 篇 15 题，混着听力）。
66 套目录上线后它们既重复年份、又不符合「4 篇阅读 + 30 题」的结构，所以置 `hidden = true`：

- 不出现在试卷列表、不进闯关抽题；
- 数据与历史作答都保留（不删记录，`Answer` 照旧挂在题目上）；
- 管理页仍然可见，标「已隐藏」，需要时可以把 `hidden` 改回 false。

刷题页对「卷不存在 / 非 ready / 已隐藏」一律跳回首页试卷区，三种情况不会让人停在空页面上。
