## 1. 测试概述

### 1.1 本轮改动范围

按需求拆成四块，逐块给了验收口径：

| # | 需求 | 交付内容 | 验收口径 |
|---|---|---|---|
| 1 | 试卷内容不完整、听力缺音频 | 66 套卷补齐听力 25 题（8 段材料 + 原文）；隐藏 2 套只有 15 题的旧演示卷；听力改用系统朗读现场出声 | 每套题量 = 写作 1 + 听力 25 + 阅读 30 + 翻译 1 = 57；听力段段有原文且能出声 |
| 2 | 试卷区缺年份筛选与搜索 | 试卷库加年份、关键词、只看完整卷三个筛选，状态落 URL | 筛选可叠加、可分享、刷新不丢 |
| 3 | 闯关凌乱、玩法重复；音频与做题不一致 | 闯关按「词汇反应 / 听 / 读写」三区重排；合并重复的「单词消消乐」卡片；新增听写关卡；播放器与做题共用同一引擎 | 三区结构正确、无重复入口、听写逐词判分正确 |
| 4 | 出测试报告 | 本文件 | 覆盖可证、缺陷分级、结论明确 |

### 1.2 测试方法

- **数据审计**：`scripts/audit-papers.mjs` 直连库，按板块核对题量，不依赖 `status` 字段自证。
- **端到端脚本**：`scripts/verify-listening.mjs`、`verify-reading.mjs`、`verify-all-types.mjs`、`e2e-pages.mjs`，Puppeteer 真浏览器操作，断言落在 DOM 文本与按钮状态上。
- **纯函数单测**：`scripts/test-dictation-judge.ts`，判分逻辑 8 条断言，覆盖全对、拼错、漏写、多写、空答、半句、标点归一化。
- **线上复核**：同一套 E2E 脚本把 `CHECK_BASE` 指向线上域名、带 `sharecode` 再跑一遍，避免「本地绿、线上旧」。

> 语音朗读在无头浏览器里没有发音引擎，E2E 注入了一个形状与真实 API 一致的假 `speechSynthesis`（按句回调 `onstart/onend`），用于稳定验证「播放状态 → 逐句高亮 → 下一题锁定 → 播完解锁」。**真实出声**由有声卡的浏览器人工确认，未纳入自动化。

### 1.3 环境

- 本地：Windows，Node 22.22.2，Chrome（headless new），dev server `127.0.0.1:3010`。
- 线上：Node 服务单端口，SQLite 运行库位于 `$HOME/.cet-data/cet.db`，经 `prepare-db.mjs --keep` 复制后由 `import-papers.mjs` 写入题库。

### 2.2 内容完整性（需求 1）

审计结果：

```
可见卷 66 套：完整 66 / 不完整 0
级别分布：四级 33 套 · 六级 33 套
听力材料：530 段，含原文 530 段，含音频文件 0 段
```

- 66 套全部达到 57 题：写作 1 + 听力 25 + 阅读 30 + 翻译 1。听力按官方结构组织为 **短篇新闻 3 段（3+2+2=7 题）/ 长对话 2 段（4+4=8 题）/ 篇章 3 段（4+3+3=10 题）**，题号 1–25 连续。
- 每段材料都带逐句 `transcript`（含起止秒数），530 段无空原文。
- 两套旧演示卷（`paper-cet4-2024-12`、`paper-cet6-2024-06`，各 15 题）已隐藏，作答数据保留；首页与闯关不再出现。依据：这两套被 2021–2026 目录卷完全覆盖，留着就是「点进去是残缺卷」。

**关于音频来源的处理**：四六级真题录音由考试机构授权给新东方、中公等渠道，其站点明确标注「仅供个人学习使用，请勿用于商业传播」，不能打包进公开站点分发（检索见 §数据来源清单）。因此本轮不导入官方录音，改为**用听力原文现场合成朗读**：零音频文件、零版权风险、每套卷都能立刻出声，并且天然支持 0.85× 慢放与逐句重播。播放器保留 `<audio>` 分支，将来若拿到授权音频，填 `audioUrl` 即自动切到真实录音，无需改前端。

## 4. 缺陷统计

本轮测试与改造过程中发现并处理的缺陷，共 9 项，无遗留 P0/P1。

| 编号 | 级别 | 现象 | 根因 | 状态 |
|---|---|---|---|---|
| D-01 | P0 | 66 套卷听力 Section 全部 0 篇材料，点进去只有「音频暂缺」 | 正文 JSON 只有写作/阅读/翻译，导入器按 `passages.length > 0` 判定，空 Section 直接跳过 | 已修（生成器 + 导入） |
| D-02 | P1 | 两套 2024 年旧演示卷只有 15 题，仍出现在列表 | 早期种子数据，被目录卷覆盖但未隐藏 | 已修（`hidden=true`，作答保留） |
| D-03 | P1 | 听力 8 段材料只能看第一段，无法切到下一段 | 段落导航只在阅读板块渲染；听力最后一句题被 `isLast` 挡住 | 已修（导航 + 跨段切题） |
| D-04 | P1 | 播放中可直接点「下一题」，音频还没听到就跳走 | 切题按钮无播放状态约束 | 已修（锁定 + 显式出口） |
| D-05 | P2 | 听写中间写错一个词，后文全部判错，9 个正确词只得 20% | 判分按下标逐位比对，错位连坐 | 已修（LCS 对齐，补 8 条单测） |
| D-06 | P2 | 听写第一句不朗读，要点「播放句子」才有声 | `start()` 里 `setTimeout` 读到的是上一轮 state（`rounds` 尚未生效） | 已修（直接传首句文本） |
| D-07 | P3 | 试卷副标题把 8 段材料名全列出来，一行被截断且噪声大 | 直接 `join(" · ")` 篇名 | 已修（按板块汇总题量） |
| D-08 | P3 | 4 个验收脚本自身判据过期，报假失败 | 断言写死旧 UI（`audio` 元素）、旧卷 id、`legacy.css` 以独立 link 加载、`X-AI-Mode=mock` 判旧版 | 已修（改判据 + 说明） |
| D-09 | — | 真题听力音频无法导入 | 版权限制，官方仅授权渠道分发 | 设计约束，改走合成朗读（§5.1） |

缺陷密度：9 项 / 66 套 × 57 题（3762 题）≈ 0.24 项/百题；其中内容层 2 项、交互层 2 项、算法层 1 项、展示层 1 项、测试资产 1 项、设计约束 1 项。P0 与 P1 全部在发布前关闭。

D-08 值得单独说一句：**过期断言比没有断言更危险**。`check-live-version.mjs` 曾用 `X-AI-Mode: mock` 判定「线上是旧构建」，而当前代码在未配置服务端 Key 时本就返回 `mock`，这条判据会把新版本判成旧的；`verify-all-types.mjs` 的移动端用例还在打开已被隐藏的旧卷 id，于是每次跑都产生两条 404 噪声，看起来像页面报错。本轮把这些判据改成「新路由是否存在」「故意 404 不计入页面报错」「样式包里是否有降级规则」，测试资产本身也进入了回归范围。

## 5. 风险与建议

### 5.1 听力材料是仿真轮换，不是真题（高优先，需产品决策）

材料池共 14 段（新闻 6 / 长对话 4 / 篇章 4），66 套卷按序轮换组合。**后果**：单套卷内 8 段材料互不重复，但同一段材料会在多套卷里出现（例如 News Report One 会出现在多套）。当前展示层用的是「仿真材料」标识，未宣称真题。

建议按此顺序解决：

1. 若必须真题：走授权渠道拿到音频 + 原文，填入 `Passage.audioUrl` 与 `transcript`，导入器已支持，前端自动切到 `<audio>`，无需改代码。
2. 若维持仿真：把材料池扩到 60 段以上，按「材料指纹」去重分配，保证一个材料在一个级别内最多出现 2 次；`gen-listening.mjs` 的 `pickMaterial` 已集中在一处，改分配策略不影响其他模块。
3. 无论走哪条，都应在首页明示「仿真卷 / 真题卷」比例，避免用户误当真题模考。

### 5.2 朗读依赖浏览器语音引擎（中）

- 桌面 Chrome / Edge 有稳定英文音色；部分安卓内置浏览器、无语音包的系统会无声或音色生硬。
- 已做：不支持时明确提示「请用 Chrome / Edge 打开」，句间留停顿，支持 0.85× 慢放。
- 未做：音色选择、离线音色回退。若目标用户大量使用微信内置浏览器，建议补一版「下载 20 段授权音频 + 其余走合成」的混合方案。

### 5.3 线上数据非持久（中，长期）

运行库仍是沙箱内 SQLite（`$HOME/.cet-data/cet.db`），每次重新发布会被重置为种子库，用户当次产生的作答/生词/听写成绩会丢。本轮发布已重置一次。若要长期运营，需换托管 Postgres；Prisma schema 迁移路径已在文件头注明（`provider` 改 postgresql、JSON 字段改回 Json）。

### 5.4 闯关玩法仍是「词↔义」为主（低）

合并了重复入口，但 8 个词汇关卡机制仍有重叠（消除/打地鼠/贪吃蛇/打字守卫本质都是「看释义点词」）。这是刻意保留的：换手感能降低疲劳，但真正的能力覆盖仍集中在「认词」。下一步若要提升迁移价值，优先做「句子级输出」类关卡（听写已补一个），而不是再加一个点词游戏。

## 6. 结论

1. **需求 1（内容与音频）**：66 套卷全部达到 57 题，听力 8 段材料、530 段原文齐备；音频走系统朗读，能出声、能慢放、能逐句重播，且不与做题脱节。真题音频因版权未导入，属已知限制，不是缺陷。
2. **需求 2（筛选）**：年份、关键词、只看完整卷三条件可叠加，状态落 URL，可分享可刷新。
3. **需求 3（闯关与音频一致性）**：三区重排完成，重复入口合并，新增听写关卡并与做题共用同一朗读引擎；播放中锁题，杜绝「没听到就跳下一题」。
4. **质量水位**：本地 153 项校验（87 条用例 + 66 套卷审计）、线上 43 项用例全部通过；P0/P1 缺陷 0 遗留；线上三个关键页 TTFB 222–258 ms。

**上线判定：通过。** 唯一需要产品侧拍板的是 §5.1 的「仿真轮换材料」定位与后续扩容/授权方案。
