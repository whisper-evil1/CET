## 五、本轮发现并修复的问题

1. **老内核下正确/错误色块缺失**（影响练习页选项与错题页 ✓/✕ 语义色）。
   `legacy.css` 只覆盖了 `text-correct/text-wrong`，未覆盖 `bg-correct(-soft)`、`bg-wrong(-soft)`、`border-correct/wrong`。
   → 已补规则（注意 solid 先写、soft 后写以正确覆盖），复测：`correctBg=rgb(232,242,236)`、`wrongBg=rgb(248,233,230)`。
2. **错题分布条在老内核不可见**：原用 `h-2/absolute` 等 Tailwind 工具类，无 `@layer` 时高度塌成 0。
   → 改为内联几何（120×8、absolute、圆角、背景），任何浏览器都能画出。
3. **错题 AI 面板「停止」误伤**：点击停止会清空已生成内容并误报“超时”。
   → 区分「用户停止 / 超时 / 真实错误」：停止保留部分内容不报错，超时保留并提示，真实错误才清空。
4. **线上网关 sharecode 缺失（只在生产环境暴露的真实缺陷）**：错题 AI 面板用裸 `fetch("/api/mistakes/analyze")`，未带 `?sharecode`。workbuddy.host 网关在 `__wb_rsc` cookie 丢失（隐私模式、手机百度/迅雷/微信 WebView、cookie 过期）时会直接 403「链接不完整」，请求到不了应用层——本地正常、上线才坏。
   → 改用 `withSharecode()` 拼接，并加 `isPlatformBlock()` 识别平台拦截页给出引导文案。浏览器实测请求 URL 为 `/api/mistakes/analyze?sharecode=TESTSHARE…`。
5. **同类缺陷（既有功能顺带修复）**：`writing-translation-pane.tsx` 的写作/翻译 AI 批改也是裸 `fetch("/api/ai/chat")`，同样补 `withSharecode()` + `isPlatformBlock()`。

## 十二、跨浏览器 / 跨设备全功能核查（2026-11-02 深夜，本地已验证，未上线）

### 12.1 先说结论：真正卡住老浏览器的不是 CSS，是 JS 语法

以前只做了 CSS 兜底（`legacy.css` + `data-css-fallback`），页面能"看得见"。但脚本这一关没查过：
Next 15 默认按现代语法出包，**一个 `?.` 就能让老内核整块 chunk 解析失败**——样式在、字能读、按钮全死。

用 acorn 逐文件试解析（新增 `scripts/syntax-floor.mjs`），量出改动前的真实门槛：

| 产物 | 语法底线 | 谁写的 |
| --- | --- | --- |
| `95026029-*.js`（69KB） | **ES2022**（class static 块） | `@tencent-ai/workbuddy-cloud-sdk` |
| `4678-*.js`（172KB） | ES2020（`?.` / `??`） | markdown 栈 |
| `main-*.js`、`1255-*.js` | ES2018 | Next 自身运行时 |

也就是说：**改动前 Chrome < 94、Safari < 16.4 打开就是白交互**。这跟"手机能用"直接冲突。

### 12.2 改法

1. **把 ES2022 那一档降下去**：`next.config.ts` 加 `transpilePackages: ["@tencent-ai/workbuddy-cloud-sdk"]`。
   只降这一个包（它是唯一用 class static 块的），底线从 ES2022 → **ES2020 = Chrome 80 / Safari 13.1**。
   再往下压不动：`main-*.js` 里那两处 `?.` 是 Next 运行时，改不了；也不必要——ES2020 已经覆盖 iOS 13.4–16.3 这批机器。
2. **补运行时内置方法**（`src/lib/compat-scripts.ts`，内联进 `<head>`，纯 ES5）：
   `Array.prototype.at`（Next 自己的 flight 解析器在用，缺了直接 TypeError）、`String.prototype.at`、
   `Object.hasOwn`、`Object.fromEntries`、`String.prototype.replaceAll`、`Promise.allSettled`、
   `Array.prototype.flat/flatMap`、`globalThis`、`queueMicrotask`、`structuredClone`。全部特性检测，有就不动。
3. **语法都解析不了时给人话**：`new Function("… ?? …")` 探测 ES2020 语法，失败就插一条可关闭的提示条，
   说明"内容能读、交互可能不可用、建议升级"。另外补了 `<noscript>` 提示。
4. **顺手修掉三处真实的窄屏问题**（320px = iPhone SE 一代）：
   - 错题页 grid 子项缺 `min-w-0`，被内容顶到 377px，整页横向滚动（57px）；
   - 个人中心邮箱是长串且不换行，320px 下把页面顶宽 19–33px → 头部允许换行、邮箱省略号；
   - 顶栏导航原本 `overflow-x-auto`，"我的"被裁在滚动区外 → 小屏改为换行。
5. **iOS 专项**：输入框在 ≤640px 一律 16px（iOS 聚焦会自动放大整页）；抽屉补 `env(safe-area-inset-bottom)`；
   练习页整屏容器 `100vh → 100dvh`（地址栏伸缩时底部"提交答案"会被挤出屏幕且滚不到）；
   `-webkit-text-size-adjust: 100%` 防横屏字号膨胀。
6. **color-mix 兜底**：Tailwind v4 的半透明底色靠 `color-mix()`（Chrome 111+）。Chrome 99–110 认得 `@layer` 却不认 `color-mix`，
   顶栏会变透明、滚动时文字互相压。用 `@supports not (...)` 只在真不支持时补不透明底色。

## 十三、线上产物的语法底线实测（2026-11-02 补）

### 13.1 踩到的坑：一轮无效结论

第一版脚本用 `fetch` 抓 chunk，得到 9 个文件**体积完全一样（各 3KB）**，acorn 全部返回 `ESnull`，
最后打印「线上产物最严一档：ES9」——这个结论是假的。原因：workbuddy.host 网关要求**每个**请求
都带 `?sharecode=`，漏带时返回约 3KB 的错误页，且 HTTP 状态仍是 200、`content-type` 是 `text/html`。
浏览器里正常，是因为 sharecode 由前端路由带着走，而脚本是裸 `fetch`。

修正后加了三条硬校验，任何一条不过就判定「抓取无效」而不是硬出一个结论：

1. `content-type` 必须是 `javascript`；
2. 正文不得以 `<!doctype` / `<html` 开头；
3. 全部 chunk 体积不得完全相同（错误页的典型特征）。

### 13.2 采集范围：不只看首页

从 `performance.getEntriesByType("resource")` 取实际加载的 chunk 地址，再回 Node 逐个下载解析。

### 14.1 用户报的现象

写作 / 翻译页面的「AI 批改」反馈里：

1. 正文出现裸露的 `**` 星号（没有按 Markdown 渲染）；
2. 内容开头写着「**当前是演示模式**：还没有配置 AI Key，所以下面是内置的示例讲解；在 `.env` 里填上 `AI_API_KEY` 之后…」；
3. 给的是通用阅读技巧（「回原文扫一遍，找到同一段」「逐项排除」），对着翻译题完全答非所问。

### 14.2 根因（三层，逐一对应）

| # | 根因 | 位置 |
| --- | --- | --- |
| 1 | 写作/翻译页**没有接云通道**，直接打同源 `/api/ai/chat` | `writing-translation-pane.tsx` |

### 14.3 修法

1. **新增 `src/lib/writing-grade.ts`**（纯函数，前后端共用）
   - `buildGradePrompt()`：阅卷老师口径，翻译要求「15 分制评分 + 逐句对照 + 时态/主谓/冠词/中文标点/术语数字」，

   - `buildLocalReview()`：**没配 Key 时依据学生真实作答**逐项计算——字数（按 CET4 120 / CET6 150 分线）、
     句数、平均句长、分段、衔接词、中文标点残留、连续重复词、标点前空格、句首大小写、
     模板套话、译文与参考译文的实词覆盖率、题干数字与给定术语是否落地；给 15 分制分数 + 具体句子引用。

   失败回退 `/api/ai/grade`；正文改 `ReactMarkdown + remarkGfm`；徽标显示「云模型已接入 / 本地规则批改」。
4. **修正 `/api/ai/chat` 的 mock 文案**：去掉「演示模式 / AI_API_KEY / 填 .env」这类运维口吻，
   改为面向学生的内置讲解，并按提问意图区分「阅读解题思路」与「写作翻译采分点」。

### 14.4 修的过程中又抓到的两个真问题

**（1）中文加粗渲染不出来 —— 与截图症状同源，但不在我最初判断范围内。**

云模型输出「本题原文是关于**书法（calligraphy）**的」。按 CommonMark 的 delimiter run 规则，
闭合的 `**` 前面是全角括号「）」（Unicode 标点）、后面是汉字「的」（既非空白也非标点），
它不构成 right-flanking run，无法闭合，于是整对星号被当字面量显示。

修法：`src/lib/markdown.ts` 里的 `normalizeCjkEmphasis()`，在定界符与中文/全角字符相邻时
紧贴其**外侧**补一个零宽空格（U+200B，属 Cf 类，既非空白也非标点，正好补齐 flanking 条件）。
另加 `stripDanglingEmphasis()`：模型输出被截断导致星号不成对时直接清掉，宁可少一处加粗也不把星号甩给用户。
三个 AI 渲染点（批改、错题分析、答疑）统一走 `prepareMarkdown()`。

用 react-markdown 内部同一个解析器 `mdast-util-from-markdown` 验证：

```
前提：未处理时该句确实解析不出加粗（复现原缺陷）  strong=0，字面星号 2 个
全角括号 + 后接汉字：修复后解析出加粗  strong=["书法（calligraphy）"]
```

**（2）本地批改把「题干里的英文指令」当成原文信息 —— 误报。**

题干是「英文指令 + 中文原文」拼接，规则从整段抽数字，把 `you are allowed 30 minutes` 里的 30
也算成"原文信息"，于是学生译完原文却被判「数字没译到：原文里的 30 在译文里找不到」。
另外学生把 2000 写成 `two thousand` 同样会被判漏译。

修法：只从**含汉字的行**抽数字；作答里出现英文数字词时整条跳过数字核对（宁可漏报，不要误报）。

### 14.5 顺带修的延迟问题

本地批改是同步算出来的，但复用了 mock 的打字机流（15–35ms/片），848 字要滴 7 秒以上——人为拖慢。
给 `streamStaticText()` 加 `instant` 选项，本地规则批改与本地错题分析改为整段直出。

### 15.3 上线后又抓到一个我自己的错——零宽空格插错侧

第一次线上复测时写作批改仍报「有裸露 `**`」。用探针把上下文抓出来：

```
逗号是**中文标点"，"**，四六级考试会扣分
```

这处**本来就合法**：闭合 `**` 前是引号（标点）、后是全角逗号（标点），满足 CommonMark 的 2b 分支。
但我的预处理不区分开/闭标记，两侧都补了零宽空格——闭标记后面补了 ZWSP 之后，
「后面是标点」变成了「后面不是标点」，2b 不成立，于是本来能渲染的加粗反而坏了。

修法：按角色分别判定。
- 开标记需满足 left-flanking：`非空白(后) && (非标点(后) || 空白/标点(前))`
- 闭标记需满足 right-flanking：`非空白(前) && (非标点(前) || 空白/标点(后))`
只在**该角色确实不合格**时才往内侧补 ZWSP；并记录落单开标记的位置，收尾时精确摘掉它，
而不是把整段的星号一起删。

新增两条回归用例锁死这个坑：
- 「闭标记前后都是标点时原样保留（不补零宽空格）」→ 输出必须与输入完全相同
- 「开标记后紧跟全角引号时能解析出加粗」→ 该补的仍要补

`test-markdown-cjk.mjs` 现 **20/20**。

### 15.4 测试脚本自身的四个坑（都修在脚本里，不影响产品）

线上复测一开始大面积假失败，逐个查清后确认全部是脚本问题：

1. **冷启动占位页**：`server.cjs` 先 listen、再后台编译启动 Next。冷启动期间所有请求拿到
   「正在启动」的 HTML（HTTP 200）。→ 注册「成功」其实没建号，登录必然失败；
   产物检查还会误报「缺 polyfill / 缺 CSS」。修：各脚本先轮询 `/api/auth/csrf` 直到返回 JSON。
2. **注册只看 `res.ok`**：占位页也是 200。修：必须校验 `content-type: json` 且 `code === 0`，
   占位页等 15 秒重试，429 等 25 秒重试，仍失败则 `exit(2)` 并说明是环境问题。
3. **hydration 抢输入**：登录页是客户端组件，React 接管时会把 SSR 的输入框重置为空，
   在此之前 `page.type` 的值会被清掉，表单以空值提交并报「邮箱或密码不对」。
   修：输入后**校验输入框的值**，不对就重试；所有页面操作包 try，抛错时若已离开 `/login` 即视为成功。
4. **重复实现导致漏洞重复**：上面这套登录逻辑原先在四个脚本里各写一遍，改一处漏三处。
   已抽成 `scripts/lib/login.mjs`（`loginViaUi`），四个脚本统一调用。

### 16.2 「高频」的依据（可核验，不是拍脑袋）

词书从 `node_modules/ecdict/assets/ecdict.csv` 生成，用的是该数据集自带的两个**真实语料词频**字段：

- `frq` —— COCA（当代美国英语语料库）词频排名，5709 / 5802 个四六级词有值（98.4%）
- `bnc` —— BNC（英国国家语料库）词频排名，5738 / 5802 有值（98.9%）

取两者中更靠前的名次作为 `rank`，越小越常见。筛选与排序规则：

| 词书 | 规则 | 实际规模 | 首位 → 末位 |
|---|---|---|---|
| `cet4-core` 四级高频 | 含 CET4 标签，按 rank 升序 | 1500 | government(124) → psychological(2361) |
| `cet6-core` 六级高频 | 含 CET6 且不含 CET4（六级新增词），按 rank 升序 | 1500 | environmental(819) → rectangle(10058) |
| `cet-essential` 必备核心 | 柯林斯 ≥4 星或牛津核心词，且属四六级考纲 | 800 | government(124) → fairly(1413) |

每条词书只存 `word/rank/collins/oxford`（合计 137 KB），释义统一从 `data/offline-dict.json` 取，
避免同一单词在两处出现不同释义。词书数据不进浏览器包：`/vocab` 首屏 chunk 9.88 kB 未变。

### 16.3 优先级算法（四因子 + 真题语境）

```
score = 100 × (0.30×考纲 + 0.28×词频 + 0.27×紧迫 + 0.15×薄弱)
        × (已掌握 ? 0.45 : 1) + (有真题语境 ? 3 : 0)
```

| 因子 | 取值 | 为什么这么算 |
|---|---|---|
| 考纲 | cet4=0.95、cet4+cet6=1.0、cet6=0.85、gk/ky=0.7、无=0.55 | 先保证「考不考」 |
| 词频 | `1 - log10(min(rank,20000)) / log10(20000)`，无数据取 0.5 | 对数压缩，避免前 100 名吃掉全部差异 |
| 紧迫 | 未学过=1；未到期≈0.15；逾期 = 0.35 + 逾期天数/7（上限 1） | 刚背完的词不该立刻重排到最前 |
| 薄弱 | 0.6×失误率 + 0.4×(1 − 连对/3) | 老错的词该被顶上来 |

调度（`scheduleReview`）用简化 SM-2：

- 答对（good）：间隔沿固定序列 1 → 2 → 4 → 7 → 15 → 30 天，之后 ×ease（上限 365）
- 答错（again）：间隔归零、`dueAt = now + 10 分钟`、ease −0.2（下限 1.3）、lapses +1、连对归零
- hard：间隔 ×1.2、ease −0.15；easy：间隔 ×ease×1.3、ease +0.15（上限 3.2）
- 掌握判定沿用旧口径「认识满 3 次」，不改变老用户的词表分组

### 16.7 开发过程中被测试抓出的三个真缺陷

1. **分隔符按「数组顺序」匹配而不是「出现位置」**
   `abandon | vt. 放弃, 抛弃` 被更靠后的英文逗号切开，单词变成 `abandon | vt. 放弃`，整行被拒。
   → 改为取最早出现的分隔符；同时把「；」从词/释义分隔符里移除（它是义项分隔符，
   `abandon n. 放弃；抛弃` 曾被切成词 = `abandon n. 放弃`）。
2. **词性标记没从单词里剥离**
   `- ambiguous  adj. 模糊的` 里单词部分成了 `ambiguous  adj`，双空格导致校验失败整行被拒。
   → 用 `TRAILING_POS` 把尾部 `adj.`/`n.` 剥出来归还给释义。
3. **`word` 这个词被当成 CSV 表头吃掉**
   原逻辑「词头 === word 且有释义 → 跳过」，用户真要导入 `word` 时会被静默丢弃。
   → 只在该行释义形如 `definition/translation/释义` 时才判为表头。

另外补了一处数据完整性缺口：v2.1 之前入库的词没有 `examRank`/`examTags`，
优先级会永远吃默认值。导入时增加「只补空字段、不动复习进度」的回填逻辑。

### 17.7 本轮 9 个「失败」全是验收脚本自身缺陷

第一次线上跑出现 40 通过 / 9 失败，逐条查完确认**没有一条是应用缺陷**，都是脚本判定写错了：

1. **按钮文案带图标，精确匹配永远找不到**
   `clickAndWait("开始刷词")` 用 `textContent.trim() === "开始刷词"` 找按钮，
   而按钮实际文案是 `🎴 开始刷词` → 从未点击 → 「刷词卡片可打开」「答对后提示下次复习时间」两连挂。
   → 匹配策略改为「先精确、找不到再按包含取最短文案」。
2. **拿 placeholder 当「页面已渲染」的判据**
   `document.body.innerText` **不包含** placeholder 属性文本，用「搜索单词或释义」判列表页永远不成立，
   于是排序按钮根本没被点，白判一次「排序不递减」。
   → 改为探测 `input[placeholder*="搜索单词"]` 是否存在。
3. **优先级徽标取错 span**
   原逻辑取「li 内第一个纯数字 span」，`0/3` 之类的复习次数标记会干扰；且 `document.querySelector("ul")`
   取的是页面上第一个 `ul`（可能不是主列表）。
   → 改为取 `li` 最多的那个 `ul` 作主列表，徽标取带 `title` 的 `span`（组件里它带 `title={reason}`，唯一）。

修正后重跑 **49/49 全通过**，同一份线上部署、同一个账号流程。

参考图是「蓝紫渐变 + 玻璃卡片流」，而本项目正文是**衬线纸感排版 + 朱砂印章**
（`--color-paper` / `--color-ink` / `--color-seal`）。两套底色硬拼会出现两个问题：
渐变卡在米白纸底上显得脏，玻璃拟态的半透明叠在衬线正文上会吃掉笔画对比度。

所以只借了两样东西，其余保留原设计语言：

| 借来的 | 具体做法 | 不借的 |
|---|---|---|
| 卡片节奏 | 统一 `--radius-soft: 16px` + `--shadow-soft`（两段阴影，无图片请求） | 蓝紫渐变背景 |
| 游戏化信息层级 | SVG 进度环、星级、连击数、`x/10` 计数 | 玻璃拟态、发光描边 |
| 功能区色 | 5 个低饱和 tint 每区一色，只做**卡片底色**，正文仍是墨色 | 高饱和主色大面积铺 |

tint 与墨色成对定义在 `globals.css` 的 `@theme` 里，对比度按正文可读取的：

```
--color-tint-jade:  #e9f2ec  / --color-jade-ink:  #2f6b51   背单词
--color-tint-amber: #faf0dd  / --color-amber-ink: #8a6420   阅读
--color-tint-indigo:#ebedf9  / --color-indigo-ink:#43457f   写作翻译
--color-tint-rose:  #fbece7  / --color-rose-ink:  #8f4a38   小说英译
--color-tint-sky:   #e7eff5  / --color-sky-ink:   #3a5f78   短视频出海
```

首页 Hero 的纸纹用 `radial-gradient` 两层叠色实现（`.hero-paper`），**不加载图片**——
省一个请求，也避免旧内核在 `background-blend-mode` 上的差异。

### 18.4 关键决定：游戏不另建一套进度

这是本轮最容易做错的地方。游戏化如果自己记分、自己记进度，就会变成
「游戏里 10 级，生词本里还是 0 词」——两套数据互相打脸。所以三关全部挂回原系统：

| 关卡 | 题从哪来 | 结果写到哪 |
|---|---|---|
| 背单词 | `/api/vocab/queue`（按优先级排好的今日队列） | `/api/vocab/[id]/review`：答对 `grade=good`（间隔推进），答错/超时 `grade=again`（10 分钟后重来） |
| 阅读 | `/api/papers` 真题（只取有 ≥2 选项的客观题） | `/api/answers` → 进错题本，与刷题主线同一份记录 |
| 写作 | 真题里的写作/翻译题 | `/api/ai/grade`（无 Key 时退化为字数/句长/衔接词/中文标点检查） |

干扰项也不造数据：从同一个词库里取别的词的释义，去掉重复与过短释义。
也就是说——**玩完这一关，生词本/错题本里真的前进了**，不是另一个平行进度条。

### 18.5 生成通道三级降级，且必须如实标注

小说英译与短视频出海都要出英文，但云端模型不一定可用。三级降级写在 `creation-client.ts`：

| 优先级 | 通道 | 触发条件 | UI 标注 |
|---|---|---|---|
| 1 | WorkBuddy 云模型 `cloud.llm` | 线上主力，凭证域名匹配 | `云模型` |
| 2 | `POST /api/create/generate` | 云不可用（本地开发、域名不匹配） | 配了 `AI_API_KEY` → `服务端模型` |
| 3 | 离线骨架 | 服务端也没 Key | `离线骨架` + `未配置模型` 小字 |

两条工程细节：

- **模型探测加 4 秒超时**（`MODEL_PROBE_MS`）。`cloud.llm.models.list()` 在本地会**挂住不返回**，
  原来每次生成要白等十几秒才落到服务端通道；加超时并在挂载时 `warmUpCloud()` 预热后，
  实测从约 10s 降到 6s 内落到服务端。
- **服务端也失败就抛错**，不静默返回半截内容。宁可让用户看到「重试」，也不给一段假英文。

### 18.6 「离线骨架」不是译文——这是刻意的

模型不可用时，输出的是**可执行的创作任务单**：每段该讲什么、专名统一规则、
英文句式模板、平台硬规则（标题 ≤60 字符、标签不能带空格、每个镜头必须有口播）。
页面上明确打 `离线骨架` 标签，并附「去配 `AI_API_KEY` 就会出真译文」。

理由很直接：伪造一段机器英文比不给更糟——用户会以为那就是译文，拿去发布。
所以宁可输出「这里该写什么」，也不输出「一段看起来像英文的东西」。

### 18.7 本轮发现并修复的真缺陷

**`reviewSchema` 的 `result` 是必填项，导致闯关写回 400。**

闯关只需要传 `{ grade: "good" }`，而原 schema 要求 `result: "known" | "unknown"`。
线上同样会 400（不只是测试脚本的问题）——即「闯关里答对，进度不前进」。
修法：两者都改 optional，再用 `.refine` 要求至少给一个：

```ts
export const reviewSchema = z.object({
  result: z.enum(["known", "unknown"]).optional(),
  grade: z.enum(["again", "hard", "good", "easy"]).optional(),
}).refine((v) => Boolean(v.result || v.grade), { message: "需要 result 或 grade 之一" });
```

另有一条**脚本**问题（不算应用缺陷）：注册接口按 IP 限流 429，同一台机器连跑
Chrome / Edge 两遍就会撞上，整套验收在第一行就崩。改为撞 429 时回落到演示账号继续跑，
日志里标注「注册限流，改用演示账号」——后面的断言验的是功能，不是「能不能注册」。

## 二十、v2.4 游戏化改造 + 单词可视化数据面板（2026-11-08，**本机已验证，未上线**）

> 本轮用户要求原话：「这些趣味**全以游戏的形式**开发，**单词需要可视化数据分析面板**（加在适当的位置上）……这些弄好后必须保证所有的浏览器都可以正常运行，所有功能都能正常执行，无论是手机和电脑都能正常运行」。
> 本节只记录**本机**验证结果。用户本轮未下达上线指令，线上仍是 v2.3（见第十九节）。

### 20.1 「游戏化」怎么落地（不是套个皮肤）

原来的三关只是「有倒计时的练习页」。这轮先抽出共用零件 `src/components/arcade/game-hud.tsx`，
把三关统一到同一套游戏语汇，再分别加机制：

| 零件 | 作用 | 实现约束 |
|---|---|---|
| `Hearts` | 3 条命，答错/超时扣 1，扣光提前收关 | SVG 心形，`fill` 直接内联，不依赖图标字体 |
| `ComboBadge` | 连击 ≥2 才出现，答错清零 | 无动画库，用已有 `pop` keyframe |
| `TimerRing` | 每题倒计时环，剩 25% 转朱砂 | `stroke-dasharray` 手写，**不用** `conic-gradient` |
| `LevelDots` | 关卡点阵：绿=对、朱=错、墨=当前、灰=未做 | 纯色块，无 canvas |
| `StarRow` | 结算星级（0–3） | 与点阵同源，避免两套评分标准 |

各关差异（有意保留，不是漏做）：

- **背单词**：命值 + 连击 + 每题 12 秒环 + 分数。命扣光 → 「命用完了 · 提前收关」，已答的题照常写回 SRS，不白答。
- **阅读**：命值 + 连击（用「末尾连续答对数」而不是历史对率，避免答对 3 题后答错 1 题就连击归零）。
- **写作**：**不用命值**——写作没有「一次答错」的判定，扣命逻辑硬套会变成随机惩罚。改为「限时 15 分钟 + 字数目标条」（CET4 120 词 / CET6 150 词），到点提示、达标显示「已达标 / 差 N 字」。

### 20.2 数据面板放在哪、为什么放这

面板是独立页 `/vocab/stats`，**不塞首页**：首页是「今天该干什么」，面板是「我到底学成什么样」，
两件事混在一屏会把今日任务的行动按钮挤下去。入口四处，覆盖四条动线：

1. 生词本顶部「学习数据 →」（想查的时候在这）
2. 背单词结算面板「看学习数据」（刚打完一关，最有动力看）
3. 首页「学习三步」标题旁 + 数据概览底部（顺路发现）
4. 闯关总览页入口卡（从游戏进来的人）

### 20.3 新增数据表：为什么非要加

`VocabWord` 只有**当前快照**（interval、reviewCount、status），算不出「近 14 天每天复习多少」
「间隔拉长后还记得多少」「连续几天没断」。所以加一张只追加的流水表：

```prisma
model VocabReview {
  id           String   @id @default(cuid())
  userId       String
  user         User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  wordId       String
  grade        String   // again | hard | good | easy
  isCorrect    Boolean
  intervalDays Int      @default(0)
  reviewCount  Int      @default(0)
  createdAt    DateTime @default(now())
  @@index([userId, createdAt])
  @@index([wordId])
  @@index([userId, isCorrect])
}
```

落地方式：`prisma db push`（**纯加表**，不动老表结构，老数据零迁移）。
写入点在 `/api/vocab/[id]/review`，且 `.catch(() => null)` —— **流水写失败不能连累复习本身**。

### 20.4 五张图的口径（这块最容易造假，逐条写清）

| 图 | 取数 | 口径陷阱 |
|---|---|---|
| 掌握度环 | `VocabWord.status` 快照 | `fresh ⊂ learning`。总数必须用「各段之和」，不能用 `mastered + learning + fresh`（上一版就是这么算的，环上占比少了近一半） |
| 近 14 天复习量 | `VocabReview` 按天分组，缺的天补零 | 没有流水时不能画成「0 复习」，要显式说明「这份数据从今天开始记录」 |
| 未来 7 天到期 | `VocabWord.dueAt` | 只算已到期的今天 + 未来 6 天，不是「未来 7 天含今天」的重复计数 |
| 记忆保持曲线 | 按「复习时的间隔」分 5 档算正确率：首次 / 1–2 天 / 3–7 天 / 8–21 天 / 22+ | 分档依据是**当次复习前的间隔**，不是当前 interval |
| 词频与考纲覆盖 | 按词频四档，分母=该档总词数，分子=其中复习过的 | 「复习过」= `reviewCount > 0`，不是「已掌握」 |

KPI 卡片文案也据此改过：`复习中 {learning - fresh} · 未开始 {fresh}`，
否则「已掌握 0 / 学习中 0 / 未开始 11」自相矛盾（0+0+11 对不上总数）。

### 20.5 图形为什么手写 SVG、不引图表库

硬约束是「所有浏览器都能跑」。项目已定 ES2020 / Chrome 80 / Safari 13.1 底线，
引一个 60KB 的图表库只为画 1 个环和 4 组柱子不划算，且 canvas 在手机上会缩放发糊。
所以：环用 `stroke-dasharray`，柱子/进度条用绝对像素高度，**服务端直出、无 JS 也能看**。

这里踩过两个真实的坑，已在代码注释里写明原因：

1. **柱子塌成 0**：柱高一开始写 `height: "100%"`，父级是 `flex-1`（`auto` 高度），
   一路算下来没有确定高度 → 全塌成 0，「图在、柱子没了」。改为固定像素 `CHART_H = 104 / 96`。
2. **`0%` 的进度条看起来像没数据**：复习过但全错时宽度为 0，视觉上等于空。
   改为 `width: pct === 0 ? "3px" : \`${pct}%\``，留一丝可见宽度。

### 21.3 关键实现决策

1. **插画全部手写 SVG，零图片请求**（`src/components/arcade/arcade-art.tsx`）。
   项目从 v1 起就没有图片资源（纸纹都是 CSS 渐变画的），加 `<img>` 会破坏这个前提，
   而且 320 宽的小屏上图要么糊要么被裁。现在缩放不糊、服务端直出、旧内核也能解析。
2. **`preserveAspectRatio="xMidYMid slice"`**：横幅插画在手机上用「填满裁切」，
   等比缩放会在 390×124 的容器里留出左右各 80px 的空白，看着像图挂了。
3. **里程碑做了两套**：桌面用那条起伏的 SVG 路径；小屏换成 HTML 版（`MilestoneRow`）。
   原因是 SVG 按宽度等比缩放，520 的 viewBox 塞进 390 宽后 10.5px 的刻度字只剩 6px，等于没写。
4. **不用 `text-[var(--game-mute)]` 这类任意值**：Tailwind 对「只是一个 `var()`」的取值
   无法判断该生成 `font-size` 还是 `color`，会静默生成错的那条。改用 `.g-mute` / `.g-blue` 等具名类。
5. **环形 0% 时不画弧**：`strokeLinecap="round"` 在长度 0 的弧上会留一个圆点，看着像「已经有 1%」。
6. **柱图空值必须看得见**：没复习的那天用 `#e3e9f2`（原 `#eef1f6` 在白卡上等于隐形），并加一条基线。

## 二十二、v2.6 两个线上问题修复：假词题面 + 阅读无原文（2026-11-08，**本机已验证，未上线**）

> 用户反馈原话：「一个是出现很奇怪的单词（可能都没这个单词）且不要再选项里有测试词，另一个是阅读要给文章才能答题」。

### 22.1 问题一：题面是假词，选项全是「测试词一/二/三」

**现象**（用户截图）：题面 `zzzzipitrddjka`，四个选项里三个是「测试词一/二/三」。

**根因**（不是 UI 问题，是数据被污染）：

| 步骤 | 事实 |
|---|---|
| 谁写进去的 | `scripts/e2e-vocab-import.mjs` 用 base26 造测试词 `zz${stamp}a/b/c`，释义写成「测试词一/二/三」 |
| 写进哪个账号 | 该脚本固定写 **user-demo（演示账号）**，也就是用户点进去看到的那个账号 |
| 为什么没被清掉 | 清理代码在脚本末尾；只要中途任何一条断言抛错，`process.exit` 之前就跳过了清理。实测库里留下了 4 条（a/b/c/d） |
| 为什么干扰项也是测试词 | `buildRounds` 从**同一个用户词库**里取别的词的释义当干扰项。词库脏了，题面和三个干扰项一起脏 |

**修法（三层）**：

1. **清数据**：新增 `scripts/clean-junk-vocab.mjs`（默认 dry-run，`--apply` 才删）。
   判定口径 = 占位释义（`测试词/占位/待补/TODO/lorem/test word/dummy`）**或** 词形不像词
   （非纯字母、连续 3 个同字母、去掉分隔符超 24 字母）。实测命中 4 条、误判 0 条
   （`take into account` 这类真实短语安然无恙）。删除时连 `VocabReview` 流水一并清掉，不留孤儿行。
2. **堵源头**：`e2e-vocab-import.mjs` 开跑先自清 `zzzz` 前缀的残留；收尾清理也加上同一前缀。
   实测重跑时一次扫掉 **16 条**历史残留，证明这条兜底真的生效。
3. **出题层再拦一道**：`vocab-game.tsx` 新增 `isPlayable()`，占位释义或假词形的条目
   **既不能当题面，也不能当干扰项**。数据干净时它什么都不会挡。

顺带修的显示问题：选项原来用 `defText`（前 2 条释义拼起来），`country` 会带出
「[计] DOS外部命令:用于设定国家代码…」，四个选项各自三四行，卡片变长文。
新增 `defOption()`：只取第一条释义、去掉 `[经]/[计]` 这类领域标记、去重、取前 3 个义项、上限 40 字。
四个选项走同一套规则，不会只截正确项。

### 22.2 问题二：阅读只给题干不给文章

**现象**（用户截图）：题干问 "What is the main topic of the news report?"，页面上一个字都没有。

**根因**：`pickItems` 只判断「有没有选项」，于是把 **Section II 听力（短篇新闻）** 的题也抽进了阅读关。
听力题本来就没有书面原文（要靠音频），抽出来必然是一道看不到文章的死题。
库里两套卷子各有 5 篇「文章」，其中有 3 篇 `paragraphs` 是空数组 —— 正是写作/听力/翻译这三个非阅读部分。

**修法**：

1. `pickItems` 只从**有可读段落**的篇章里出题。用「有没有正文」筛而不是按 Section 标题筛，
   因为这两套卷子的 `section.kind` 是空的，标题又带编号（`Section II 听力`），按标题匹配不可靠。
2. 选卷子不再只看 `questionCount >= 5`（听力写作翻译都计入这个数），
   改成逐套取详情、按**可出题数**判断，凑不满就试下一套（最多 3 套）。
